# Правила доработки дашборда

Карта для агента, который меняет дашборд по просьбе человека. Прочитай целиком до первой правки.

## Как устроено

Страница открывается прямо с диска (`file://`), поэтому никакой сборки и никаких ES-модулей (`import`/`export`
там не работают). Все файлы — обычные `<script src>` по порядку из `index.html`. Что объявлено на верхнем уровне
одного файла (`const`, `let`, `function`), видно в следующих.

Данные человека — `dashboard-data.js` рядом со страницей, он задаёт `window.DATA`. Его собирает `engine/`.
Если счетов несколько, в `DATA` есть ещё `portfolios` — список `[{id, label, kind: 'broker' | 'account', parent?}]`
(у счёта под брокером `parent` — id брокера) и `byPortfolio` — `{id: объект того же формата, что DATA}` для каждого
брокера и счёта; сам `DATA` — «Все счета». Если счёт один, этих ключей нет. `core.js` выбирает портфель по адресу
(`#p-<id>`) или по запомненному в браузере (`localStorage 'pf-portfolio'`) и кладёт его в `D`; смена портфеля —
`selectPortfolio(id)` (новый адрес и перезагрузка страницы). Поэтому разделы и `custom.js` пишутся как обычно —
через `D`, и работают в любом портфеле. Выбранный портфель — `PF` (`PF.id`, `PF.label`, `PF.list`; `PF.cur` — `null`
во «Все счета»). В портфеле счёта или брокера бывают события `MOVE_IN` / `MOVE_OUT` (перевод бумаг с другого / на
другой свой счёт: `amountRub` — по рынку в день перевода, `cost` — перенесённая себестоимость) и итоги
`totals.movedIn` / `totals.movedOut`.
Формат этого файла в дашборде не меняй: нужны новые цифры — считай их в браузере из того, что уже есть,
или попроси доработать `engine/`.

| Файл | Что внутри |
|---|---|
| `index.html` | разметка всех разделов, порядок подключения скриптов |
| `styles.css` | оформление; в начале — токены темы (цвета, шрифты) для светлой и тёмной темы |
| `js/core.js` | выбор портфеля (`PF`, `D`, `selectPortfolio`), форматирование чисел и дат (`rub`, `pct`, `int`, `dmy`, `dLong`, `plural`), `$`, `esc`, цвета темы `C`, состояние портфеля (`P`, `SEC`, `CASH`, `TOTAL`, `LIVE`), `initCore`, `recompute` |
| `js/charts.js` | гильош первого экрана, линейный график `lineChart`, столбики `barChart` |
| `js/benchmark.js` | сравнение с индексом: `bench`, `compare`, `flowsSum`, `twr` |
| `js/live.js` | живые цены Мосбиржи, значения индексов, курсы валют (Мосбиржа, ЦБ), `refreshQuotes` |
| `js/overview.js` | раздел «Обзор» |
| `js/assets.js` | раздел «Активы» и карточка бумаги |
| `js/watchlist.js` | раздел «Избранное» |
| `js/returns.js` | раздел «Доходность» |
| `js/payouts.js` | раздел «Выплаты» |
| `js/operations.js` | раздел «Операции» |
| `js/data.js` | раздел «Данные» (предупреждения, источники, сверка со Snowball) |
| `js/app.js` | запуск: заголовок, переключатель портфеля, навигация, тема, первая отрисовка, обновление цен раз в минуту; вызывает функции из `CUSTOM` |
| `custom.js`, `custom.css` | доработки человека; обновление навыка их не перезаписывает (подробно — `references/доработка.md`) |

Поля `DATA`, которые необязательны: `title` (заголовок, по умолчанию «Мой портфель»), `cash` (валюта на счёте),
`watchlist` (исходный список избранного), `snowballRef` (блок сверки показывается, только если он есть),
`warnings` (у предупреждения можно задать `hint` — как исправить), `forecast`, `payments`, `divByYear`,
`quoteSources` (где искать цену бумаги на Мосбирже; по умолчанию — акции, режим TQBR).
Виды бумаг в `positions[].kind`: `Акция`, `Облигация`, `Фонд`.

## Что трогать нельзя

1. **`js/benchmark.js`** — правило сравнения с индексом сверено со Snowball до 0,05 %. Не менять формулы
   `bench`, `compare`, `flowsSum`, `twr`. Можно вызывать их из новых разделов.
2. **Расчёт стоимости в `js/live.js`** — функция `applyQuotes` (облигации: % от номинала × номинал × курс + НКД)
   и `recompute` в `core.js`. От них зависят стоимость, изменение за день и результат. Новый источник цен —
   отдельной функцией рядом, а не переписыванием этих.
3. **Формат `dashboard-data.js`** и всё в `engine/`. В том числе `portfolios` / `byPortfolio` и выбор портфеля
   в начале `core.js` (`PF`, `D`, `selectPortfolio`): не строить свой расчёт по счетам в браузере — портфели
   счетов и брокеров уже посчитаны тем же расчётом, что и общий. Нужен свой раздел — читай `D` (это выбранный
   портфель), а не `window.DATA`.
4. Не добавлять советов купить или продать. Внизу страницы остаётся строка
   «не является индивидуальной инвестиционной рекомендацией».

## Как добавить раздел (вкладку)

Сначала попробуй сделать раздел целиком в `custom.js` (разметка — в `CUSTOM.before`, отрисовка — в `CUSTOM.start`,
`CUSTOM.live`, `CUSTOM.redraw`; пример — в начале `custom.js`): так он переживёт обновление навыка. Шаги ниже —
если раздел всё-таки встраивается в файлы шаблона; тогда запиши правку в `МОИ-ПРАВКИ.md` в папке человека.

1. В `index.html` добавь блок по образцу соседних:
   `<section class="sec" id="goal" data-title="Цель"><div class="sec-head"><h2>Цель</h2><p>…</p></div><div class="panel">…</div></section>`.
   Пункт в верхнем меню появится сам из `data-title`.
2. Создай `js/goal.js` с функцией `renderGoal()`; данные бери из `D`, `P`, `TOTAL` и т. п., числа форматируй
   через `rub`, `pct`, `int`, текст из данных — через `esc(...)`.
3. Подключи `<script src="js/goal.js"></script>` в `index.html` **перед** `js/app.js`.
4. В `js/app.js` вызови `renderGoal()` в `start()`; если раздел зависит от живых цен — ещё и в `rerenderLive()`;
   если в нём есть график — в `redrawAll()` (перерисовка при смене темы и ширины).
5. Цвета — только через переменные из `styles.css` (`var(--accent)` в CSS, `C.accent` в canvas), чтобы работала
   тёмная тема. Новый цвет — добавь токен в обе темы в начале `styles.css`.

Вкладка внутри раздела — сегментный переключатель как «По бумагам / По видам / По отраслям»
(`.seg` с кнопками `aria-pressed`, пример — `renderStruct` в `assets.js`).

## Правила текста и чисел

- Рубли с пробелами: `rub(1234567)` → «1 234 567 ₽»; «млн» — только где мало места.
- У каждой цифры — период и смысл словами: «за год», «после налога», «прогноз» / «объявлен» / «оценка».
- Пустые случаи должны выглядеть прилично: нет данных — короткая фраза серым (`<p class="small muted">`),
  а не пустой блок или ошибка.
- Страница должна нормально выглядеть на телефоне шириной 390 px: без горизонтальной прокрутки.

## Как проверить себя

1. Открой `index.html` в браузере (рядом должен лежать `dashboard-data.js`).
2. Консоль без ошибок (предупреждения «Мосбиржа недоступна» без интернета — допустимы).
3. Ключевые числа не изменились после твоей правки, если ты их не трогал: стоимость портфеля на первом экране,
   «Прибыль за всё время», XIRR, «Выплаты за 12 месяцев вперёд», карточка «Портфель обгоняет / отстаёт от индекса»
   в «Доходности» за «1 год» и «Всё время». Запиши их до правки и сравни после.
4. Пройди по всем разделам, переключи периоды и индексы, тему (кнопка «Тема»), открой карточку бумаги.
5. Сузь окно до 390 px и пролистай страницу. Если счетов несколько — переключи портфель (в шапке) и проверь
   раздел в каждом: «Все счета», брокер, счёт.
6. Запусти проверки навыка: `node <навык>/tests/run.mjs --dashboard <папка человека>` — должно быть «ВСЁ ПРОШЛО».
